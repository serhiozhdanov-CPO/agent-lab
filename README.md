# agent-lab — Индекс зрелости здоровья: домены Р и У

Детерминированный расчёт двух доменов Индекса зрелости здоровья на
синтетических данных трекинга практик. Только стандартная библиотека Python
3.11+, никаких обращений к модели, к сети и к системному времени.

```
python3 run_demo.py            # человекочитаемый отчёт
python3 run_demo.py --json     # тот же результат в JSON
python3 -m unittest discover -s tests
```

## Структура

| Файл | Назначение |
|---|---|
| `hmi/model.py` | типы данных (`DailyRecord`, `DomainResult`), базовые операции над окном |
| `hmi/domains.py` | расчёт доменов Р и У — формулы, веса и пороги описаны в комментариях модуля |
| `hmi/synth.py` | детерминированный генератор синтетических данных (6 архетипов × 12 недель × 3 практики) |
| `hmi/report.py` | форматирование отчёта |
| `run_demo.py` | прогон на сгенерированных данных |
| `tests/test_hmi.py` | детерминизм, границы порогов, краевые случаи (28 тестов) |

## Общая шкала

Каждый домен сначала считается как сырое значение `raw ∈ [0, 1]`, затем
переводится в балл по единой таблице порогов — баллы разных доменов должны
быть сопоставимы, иначе итоговый индекс не складывается:

| raw | балл | смысл |
|---|---|---|
| ≥ 0.85 | 5 | держится сама, без внешнего усилия |
| ≥ 0.70 | 4 | устойчиво, с отдельными просадками |
| ≥ 0.55 | 3 | работает, но требует внимания |
| ≥ 0.40 | 2 | держится эпизодически |
| иначе | 1 | практики фактически не выстроены |

Если домен посчитать нельзя (мало данных, нет плана, не было ни одного срыва),
возвращается `score = None` с полем `reason`. Подставлять в такой ситуации 5
баллов нельзя: отсутствие наблюдения — не доказательство зрелости.

## Домен Р — регулярность

Насколько устойчиво соблюдается ритм практик за окно 8–12 недель (по
умолчанию 12 последних полных недель; меньше 8 — домен не считается).

При `adh_w = min(1, выполнено_w / запланировано_w)`:

```
A = mean(adh_w)                          объём выполненного плана
S = 1 - min(1, pstdev(adh_w) / 0.35)     ровность недель
D = доля недель с adh_w ≥ 0.60           сколько недель «состоялись»

Р_raw = 0.50·A + 0.30·S + 0.20·D
```

Только `A` было бы недостаточно: два человека со средним 0.70 — один делает
70 % каждую неделю, другой чередует 100 % и 40 % — это разная зрелость, и
разводит их `S`. Компонент `D` отсекает случай «месяц идеально, месяц пусто».

Пороги домена: `0.35` — разброс, при котором ровность обнуляется (≈ чередование
недель 100 % / 30 %); `0.60` — доля плана, ниже которой неделя считается
потерянной.

## Домен У — устойчивость

Как быстро человек возвращается к базовой линии после срыва режима или
командировки.

1. **Базовая линия** — медиана `adh_w` по «спокойным» неделям (без пометок
   `travel` / `illness`). Медиана, а не среднее: отдельный провал не должен
   занижать планку возврата. Спокойных недель меньше 3 → медиана лучшей
   половины всех недель (факт фиксируется в `diagnostics.baseline_source`).
   Базовая линия ниже `0.35` → домен не считается: возвращаться некуда.
2. **Эпизод срыва** — максимальная серия подряд идущих 7-дневных скользящих
   окон с `adh < 0.60 × baseline`. Начало эпизода — первый день первого
   такого окна.
3. **TTR** — число дней от начала эпизода до первого окна с
   `adh ≥ 0.85 × baseline`. Возврат не найден → эпизод цензурируется:
   `TTR = 28`, `recovered = False`, счётчик в `diagnostics.censored_episodes`.

```
V = 1 - median(TTR) / 28              скорость возврата
C = восстановленные / все эпизоды     доводит ли возврат до конца
G = 1 - mean(depth),                  мелкость провала
    depth = clamp(1 - adh_дна / baseline, 0, 1)

У_raw = 0.55·V + 0.25·C + 0.20·G
```

Медиана TTR, а не среднее: одна затяжная болезнь не должна определять оценку
устойчивости целиком.

Пороги домена: `0.60 × baseline` — вход в срыв; `0.85 × baseline` — засчитанный
возврат (не «стало чуть лучше», а выход на свою норму); `28` дней — потолок и
значение для цензурированных эпизодов.

**Срывов не было** → `score = None`, `reason = "no_disruption_episodes"`:
стресс-теста не случилось, устойчивость не наблюдалась.

## Что стоит знать о методике

- **Веса** `0.50/0.30/0.20` и `0.55/0.25/0.20` экспертные, не выведены из
  данных. Вынесены в константы `R_WEIGHTS` / `U_WEIGHTS` — перекалибровка на
  реальной когорте не требует правок логики.
- **Командировка штрафуется дважды**: она снижает и Р (ритм действительно
  прерван), и участвует в У (как эпизод для замера возврата). Это осознанно:
  домены отвечают на разные вопросы — «какой ритм фактически получился» и
  «умеет ли человек возвращаться».
- **TTR систематически завышен** примерно на длину окна: эпизод привязан к
  началу первого провального окна, то есть детекция срабатывает раньше
  фактического начала разрыва. Смещение одинаково для всех эпизодов, поэтому
  сравнение людей между собой корректно, а абсолютные значения TTR читать как
  «дней с поправкой на 7-дневное окно».
- **Цензура консервативна**: эпизод в конце окна наблюдения, у которого возврат
  ещё не успел произойти, штрафуется как самый медленный. Число таких эпизодов
  всегда видно в диагностике.
