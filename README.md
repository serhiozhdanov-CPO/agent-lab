# agent-lab

Личная лаборатория для экспериментов с AI-агентами: Claude Code, Claude Agent SDK,
subagent'ы, skills, hooks и интеграции. Репозиторий — площадка для проверки гипотез,
а не production-код.

---

## План тестирования на ближайший месяц

Горизонт: **26 августа — 25 сентября 2026** (4 недели).

Формат работы: одна неделя — один блок гипотез. Каждый эксперимент живёт в отдельной
папке `experiments/NN-<название>/` со своим `README.md` (гипотеза → как проверял →
что получилось → вывод). Итог недели фиксируется в `RESULTS.md`.

### Цели месяца

1. Понять, где агент реально экономит время, а где создаёт больше работы, чем снимает.
2. Собрать воспроизводимый набор сценариев (evals), на котором можно сравнивать
   конфигурации агента между собой.
3. Довести 2–3 рабочих сценария до состояния «запускаю не задумываясь».

---

### Неделя 1 (26 авг — 1 сен) — База и измеримость

Задача недели: научиться мерить, а не «ощущать».

- [ ] Базовая структура репозитория: `experiments/`, `evals/`, `RESULTS.md`.
- [ ] `CLAUDE.md` для проекта: правила, стиль, команды. Проверить гипотезу —
      влияет ли наличие `CLAUDE.md` на качество ответов на одинаковых задачах.
- [ ] Собрать 10 эталонных задач (fixtures): 3 простых, 4 средних, 3 «злых»
      (неоднозначная формулировка, конфликтующие требования, отсутствующий контекст).
- [ ] Метрики: успех/провал, число итераций до результата, время, объём правок
      руками после агента.
- [ ] Прогнать baseline: все 10 задач без каких-либо настроек. Это точка отсчёта.

**Критерий успеха:** есть таблица baseline-результатов, к которой можно возвращаться.

---

### Неделя 2 (2 — 8 сен) — Skills и slash-команды

Задача недели: проверить, окупается ли вынос знаний в skills.

- [ ] Написать 2–3 своих skill под повторяющиеся задачи (например: разбор логов,
      подготовка релизных заметок, ревью по чек-листу).
- [ ] Проверить триггеринг: срабатывает ли skill там, где должен, и не срабатывает
      там, где не должен. Отдельно — ложные срабатывания.
- [ ] Сравнить: skill против того же промпта, вставленного руками. Есть ли разница
      в качестве и стабильности.
- [ ] Проверить, как skill ведёт себя при частичном совпадении задачи.
- [ ] Прогнать те же 10 fixtures — сравнить с baseline.

**Критерий успеха:** понятно, какие задачи стоит оформлять в skill, а какие — нет.

---

### Неделя 3 (9 — 15 сен) — Subagent'ы и параллельная работа

Задача недели: понять границы декомпозиции.

- [ ] Один агент против нескольких параллельных на задаче с широким поиском по коду.
- [ ] Проверить деградацию на длинном контексте: где агент начинает терять нить
      и помогает ли вынос части работы в subagent.
- [ ] Сценарий «исследование → план → реализация → ревью» разными агентами.
      Где теряется информация на стыках.
- [ ] Замерить накладные расходы: сколько времени и токенов стоит сама координация.
- [ ] Негативный тест: задача, которую параллелить не надо. Понять, распознаётся ли это.

**Критерий успеха:** есть правило «когда декомпозировать, когда нет», проверенное
на практике, а не на интуиции.

---

### Неделя 4 (16 — 22 сен) — Автоматизация и интеграции

Задача недели: проверить агента в петле без человека.

- [ ] Hooks: pre/post-tool, session-start. Проверить, что запреты реально запрещают.
- [ ] GitHub-цикл: агент открывает PR, реагирует на упавший CI, чинит, пушит.
      Отдельно — как ведёт себя при флаки-тестах и при конфликте слияния.
- [ ] Scheduled/фоновые запуски: что происходит, когда никто не смотрит.
- [ ] Безопасность: попытки эскалации через содержимое файлов, комментариев и логов
      (prompt injection). Проверить, что агент не выполняет инструкции из данных.
- [ ] Стоимость: сколько стоит один прогон каждого сценария.

**Критерий успеха:** минимум один сценарий работает автономно и ему можно доверять.

---

### Неделя 5, короткая (23 — 25 сен) — Разбор

- [ ] Финальный прогон всех 10 fixtures на лучшей конфигурации.
- [ ] Сводная таблица: baseline → финал, по каждой метрике.
- [ ] Список того, что не сработало, и почему — это ценнее списка побед.
- [ ] План на следующий месяц.

---

## Что осознанно не тестирую в этом месяце

- Сравнение разных моделей между собой — отдельная большая тема.
- Мультиагентные системы сложнее «оркестратор + исполнители».
- Fine-tuning и RAG над собственной базой знаний.
- Нагрузочное тестирование и продовые сценарии.

---

## Как фиксирую результат

```
experiments/
  01-baseline/
    README.md      # гипотеза, метод, результат, вывод
    runs/          # сырые логи прогонов
evals/
  fixtures/        # 10 эталонных задач
RESULTS.md         # сводная таблица по неделям
```

Правило: эксперимент без записанного вывода считается непроведённым.
